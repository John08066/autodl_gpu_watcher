# AutoDL GPU Watcher v0.8.10

监控 AutoDL 私有云入口空位、物理 GPU 显存和当前实例状态，满足条件后自动开机；另以只读SSH查看自己的训练进度、训练/测试指标和日志错误。

## 使用

打开项目根目录的 `AutoDLWatcher.exe`。保留同目录的 `_internal/` 和 `config.yaml`；不需要安装 Python，需要系统 Microsoft Edge。迁移到另一台机器时使用干净包 `dist/AutoDLWatcher-v0.8.10.zip`，再自行登录。

1. 启动后自动核验会话。登录失效时点击“登录 / 更新会话”，完成浏览器登录并关闭浏览器，再点击“已登录并关闭浏览器”。同步完成后仍需真实接口核验。
2. 选择服务器入口，填写本人用户名和采样间隔（默认60秒，平台、显存与占用名单每轮一起刷新），点击“开始监控”。打开程序本身不会启动监控。
3. 普通模式默认真实开机及无卡额度释放；开发使用 `AutoDLWatcher.exe --debug`，默认只读。勾选额度释放后，在目标空闲达标时会关闭本账号其他无卡实例，再转换或启动固定目标。
4. 点击“停止监控”或关闭窗口会等待当前请求结束。程序已关机但尚未有卡启动时停止，实例可能保持关机。

服务器表将“自动开机”和“训练SSH”分开显示：当前完整实例列表中存在匹配入口及UUID、且本地目标启用时才显示“可开机”；没有容器显示“无实例”，重建后UUID改变显示“实例已变更”，接口失败显示“未核验”。这只是开机资格，真正启动仍须满足空位、显存和账号限制；未核验或无实例入口从GUI启动时只读。训练SSH另显示未配置、待连接、已连接或连接失败，不能由容器存在推断SSH已配置。

监控入口始终对应界面选择，所选实例状态由完整实例ID查询。203的两个入口会重复展示同一张物理卡上的绑定，这不代表所选实例换了入口。

## 实时输出

每轮显示一组两行，整组成功有卡运行绿色，失败或断连红色，普通过程白色；长行可横向滚动：

```text
[12:32:02] 监控203-1 | 实例状态：有卡运行 | 动作：继续监控 | 平台空闲：203-1=0/2,203-2=0/2 | 显存达标：#1(12184MB)
  203-1[#0:用户甲,#1:用户乙]; 203-2[#0:用户甲,#1:用户乙]
```

名字与平台、显存按同一采样间隔更新，不再缓存独立的占用刷新时间。后台未提供名字时显示“用户名未知”。名字只用于显示；新版弹窗的本人归属以完整账号实例ID核验。

界面采用“AutoDL 平台”和独立服务器分页，标题显示所选编号。AutoDL左侧集中服务器列表、逐卡GPU/显存条和开机设置，右侧显示本人训练卡片。图表复用本轮Telemetry，不额外轮询；203-1与203-2共用物理卡，因此图表相同。窗口保留1000x800，底部两行日志至少容纳三轮输出，训练卡片支持滚动和只读日志详情。

登录辅助进程使用系统PowerShell绝对路径，即使启动环境的PATH中没有PowerShell目录也可运行。若系统组件确实缺失，会显示本地启动错误及具体路径并停止任务。

HTTP 200响应中的明确登录超时同样会停止GUI监控并提示重新登录；超时、429、5xx等临时故障只跳过本轮开机并重试，不误判登录过期。

v0.7.0已移除占用时长统计、SQLite历史写入、CSV导出和报表控件，只保留内存中的实时名单及开机前核验。旧占用历史文件不会再读取或更新；已有文件保留。诊断日志和连续采样状态仍在 `runtime/`。

## 训练监控与其他服务器

1. 点击服务器列表中的“训练SSH”列，或在入口右侧点“设置连接”，填写已有SSH别名、远端Python路径和可选项目目录；“＋ 添加服务器”会创建独立服务器页，例如4090。连接配置只保存在本机 `.ui/servers.json`，不保存密码、不进入Git或发行包。监控期间可为任意入口新增或保存连接；编辑其他行不会切换当前平台监控入口。运行中修改显示“已存待用”，本轮继续使用原连接，下次启动这台服务器的训练监控时生效；不需要停止其他服务器。
2. 使用Windows自带OpenSSH、已有密钥及已核验的主机记录。先在终端确保 `ssh 别名` 能登录；加密密钥需要可用的SSH代理。远端需要Linux `/proc` 和Python 3.7以上标准库；GPU信息还需 `nvidia-smi`。采集不会安装远端依赖、写脚本、修改训练或转发端口。
3. 点“开始训练监控”可单独只读采集，无须启用AutoDL开机。AutoDL点“开始监控”时也会启动该入口已配置的训练采集，两者使用同一个采样间隔，默认60秒。独立服务器页各自启动，默认60秒；切换标签不会停止后台采集，关闭窗口等待当前请求退出。
4. 默认发现当前SSH用户的 `train.py / trainer.py / train_*.py`，并结合tmux窗格进程树、训练日志或可核验GPU进程识别其他Python脚本及模块入口；继续受项目目录限制，自定义脚本列表保持严格筛选。通过已打开日志文件读取有限首尾。黑底GPU表另展示系统权限允许读取的其他GPU进程用户名、PID及脚本/配置名，不读取其他用户的训练日志、环境变量或完整命令行。脚本名支持`*`、`?`通配符，例如`train_*.py`覆盖`train_p03_t01.py`及后续同类入口；旧三脚本默认列表仅在读取时自动升级，自定义列表原样保留。可设置训练脚本名及项目目录以缩小范围；DataLoader子进程不会重复计作训练任务。只有终端输出、没有可读日志时，会显示进度不可读；tmux会话存在不代表训练仍在运行。训练原日志按钮只显示一个训练日志的最近原文，不拼接批次追踪；同一日志的新运行存活时，旧运行折叠至历史。

卡片颜色：绿色表示进程存在且有训练/测试阶段证据；红色表示已发现OOM、异常、NaN/Inf等错误，或进程退出但未找到正常完成标记（退出原因不推断）；白色表示本次没有匹配训练或有明确完成标记；黄色表示连接失败、日志不可读、过期或长时间无进展。已经观察到的任务错误在本次监控期间保持红色，断连、停止采集、日志轮换或新的普通进度输出不会清除；新进程按启动标识单独识别。断连本身不等于训练失败。

训练与每个测试集都标注自身轮次及Step，缺失数据用“—”，不会拿上轮测试指标冒充本轮。DeepfakeBench已核验使用 `range(start_epoch, nEpochs + 1)`，因此配置 `0..30` 为31轮；卡片同时显示人类轮次和原始日志Epoch。进度条仅表示此前完成轮次，不猜测轮内百分比。`Test Done!`只结束当前测试，不能证明整个训练结束。

默认120分钟没有新轮次、Step、阶段或指标时标黄，可在连接设置调整；DFDC等测试可能长时间没有日志，这只是核查提示，不是死锁诊断。重复打印相同指标不会重置进展时间。错误检测依赖可读日志，无法保证识别所有死锁或未记录的错误，也不会自动杀进程、重启训练或修改显存设置。新启动程序无法追溯此前已经结束且未被观察的任务。

GPU黑框按时间追加紧凑表格：GPU、整卡VRAM、利用率、温度、USER、PID、进程GiB、PROCESS/CONFIG；滚动查看历史，长行横向滚动。整卡显存与进程显存分列，训练卡片将显存与PID、用户、GPU合在一行；任务名、运行状态和最近进展合在首行，长内容自动换行，不截断名称。裸机按本人PID、启动时间和GPU UUID直接匹配；缺少进程显存时显示未知，不用0或整卡用量替代。

AutoDL 203容器的NVML仍无法对应本容器训练PID，因此GPU关联保持待确认。若训练日志中的PID与本任务一致，且上报`peak_gpu_allocated`，卡片可显示“显存峰值 … GiB（日志）”；这是PyTorch峰值分配量，不是当前NVML进程总显存，也不是整卡用量。未提供此字段仍显示无法核验。GPU编号以当前SSH环境为准，不能据此对齐平台INDEX；本版不注入或中断训练。

新版支持`TRAIN {...}`、`TEST/EVAL {...}`、`EVALUATED 分支 {...}`、`TRAINING_COMPLETE {...}`及明确失败事件。嵌套Loss保留分支，测试按“分支/数据集”显示；新协议的`steps_per_arm`按累计步数处理、Epoch从0转换为人类轮次，总轮数未提供则显示“—”。`EPOCH_END`只表示轮次结束，不能证明整次训练完成；`SMOKE_PASS`单独标注冒烟检查完成。日志带时区时优先使用其原始时区。无匹配任务时会提示当前脚本与目录筛选；其他格式先尝试通用指标解析；无法解释时显示原文摘要和未知状态，不把进程存在当作训练正常。

其他训练程序可以向**该训练进程保持打开的 `.jsonl` 日志**写入以下事件，无需修改监控器：

```json
{"event":"train","epoch":3,"total_epochs":20,"step":1200,"metrics":{"loss":0.21,"acc":0.91,"auc":0.97}}
{"event":"test","epoch":3,"step":1200,"dataset":"validation","metrics":{"loss":0.32,"auc":0.94}}
{"event":"completed","epoch":20,"total_epochs":20}
{"event":"error","message":"CUDA out of memory"}
```

JSONL中的epoch按1开始，step为全局步数；每个事件一行并及时flush。通用协议识别 `train/test/progress/completed/error`，`progress`事件可带 `phase: train/test`。未知日志格式仍显示进程和GPU，最近三行原文作为未解释摘要。只有可见进程且有可读输出才能分析；没有输出、无权限或仅二进制事件文件时，本地规则和LLM都无法保证恢复真实训练进度。

### 全局应用图标

标签栏右侧点击“应用图标”，选择ICO或PNG即可保存并设置当前窗口、已有弹窗及后来打开的弹窗；所有服务器页面共用，下次启动自动恢复。支持恢复默认图标，监控运行中也可更换。

- ICO按原文件字节保存，保留全部帧及作者提供的小尺寸设计，不重新编码为单帧。加载时解码各帧并通过Tk `iconphoto(False, *frames)` 显式设置窗口，保留图片对象生命周期。
- PNG保留透明度和宽高比例，居中透明补边；16、20、24、32、40、48、64、128、256各档直接从原图生成。原图分辨率及帧尺寸显示在设置页，放大不会增加原文件细节。[Pillow ICO说明](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#ico)
- 窗口标题栏、运行中任务栏、快捷方式和磁盘EXE是不同图标来源。“另存启动快捷方式”生成带当前图标的 `.lnk`；之后更换图标需重新导出。旧固定入口可能使用旧图标，需要重新固定新快捷方式；程序不清除系统图标缓存、不改动已有任务栏固定项。
- 磁盘EXE图标通过打包参数配置：`python tools/build_exe.py --stage-only --icon "C:/path/icon.ico"`（也支持PNG）。验证暂存文件后关闭旧程序再替换；运行时的图标设置不会改写EXE。未选定正式图标时，发行包保留原来的默认图标。
- 偏好在 `.ui/icon.json`，图标副本在 `.ui/icons/`，不依赖原始文件一直留在导入位置，不进入干净发行包。旧副本保留供已经导出的快捷方式引用。

图标验证分原件、转换、Tk加载及系统显示四层：345项完整回归及8项加强图标检查通过；独立新进程启动、运行中更换、Windows窗口/快捷方式/定制EXE句柄像素和标题栏/任务栏截图均已检查。当前环境实际选择16px小帧与32px大帧；未对其它显示缩放或用户尚未提供的正式图标作实机显示承诺。`WM_GETICON`为空时需检查窗口类图标，不能直接断言未加载。[Windows官方说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-geticon)

### 全局 AI 设置与任务专用监控规则

通用解析支持 JSON/JSONL、Python 字典、`key=value` / `key: value` 和带指标的 Epoch/tqdm 文本。保留自定义指标及嵌套名称；无法解释时显示原文摘要。Jupyter 内核、非 Python 程序、无可读日志或仅二进制事件的任务不保证恢复语义；AI也不能凭空知道真实训练进度。

主窗口标签栏右侧的“全局 AI 设置”适用于 AutoDL、4090 和以后新增的所有服务器。服务器页不单独保存 API 凭据或模型配置。

1. 填写 HTTPS API 基础地址、Responses 或 Chat Completions 协议、模型 ID、服务等级 `flex` / `default`（Standard）。默认选择 Flex，实际请求携带 `service_tier`；记录并展示服务端实际返回等级，未返回时明确标注。Flex 读取超时900秒，Standard 180秒，后台执行不阻塞监控。模型及接口须支持所选等级；失败继续本地监控，不自动重试或转为更贵等级。[Flex 官方说明](https://developers.openai.com/api/docs/guides/flex-processing)
2. 密钥仍独立存入 Windows 凭据管理器 `autodl-watcher/llm/`，按完整 API 基础地址绑定；不导入消息萃取-MCP密钥。公开配置在 `.ui/ai.json`，不含密钥。保存后清空密钥输入框，“已保存”不代表调用验证成功。
3. 勾选“新训练自动生成监控规则”并保存后，每个活动训练任务首次有可读日志时自动调用一次。此开关默认关闭，以免旧版用户升级后立即外发日志和产生费用。使用全局“监控提示词”中的可编辑提示词，把日志样例转换为字段映射和文本提取模板；固定JSON输出契约由程序附加。提示词可恢复默认，修改仅影响后续生成，不自动重做已有规则。各服务器按自身采样间隔执行本地规则（默认60秒），不重新调用AI、不增加SSH采样。
4. 也可在任务卡片点击“生成 / 更新监控规则”，查看、删改待发送片段后手动生成并应用。自动/手动共用全应用唯一请求队列，配置按请求启动时取快照。片段最多12000字符，遮蔽常见密钥字段；自动模式会发送该范围日志，启用前应确认可外发。关闭窗口不能撤回已发请求。
5. 规则及尝试记录存于 `.ui/training_rules.json`，按服务器连接、读取范围和进程启动身份绑定；重连/重开程序复用，同一PID的新运行不会串用。不同服务器共用全局API设置但不共用任务规则。失败、断流或程序关闭后的未完成请求不会自动再次发送，可手动更新。缓存损坏或无法保存时暂停自动请求并继续默认监控。
6. 规则只允许 JSON 字段路径及 `number/word/json` 文本占位符，不执行模型生成的 Shell/Python，不修改远端。规则必须提供真实日志样例并能提取到进度或指标；数值从每轮新日志提取，不保存AI摘要作为实时指标。按原日志记录顺序应用规则，统一沿用原行时间；未覆盖行继续默认解析，不因JSON内外时间差误拒绝，也不让旧匹配覆盖新进度。主卡片与生成窗口同步显示实际应用或回退状态；训练原日志保留。
7. 日志格式变化导致不匹配时回退默认解析，手动更新规则。规则中的训练/测试阶段可驱动显示，但不能证明进程存活或整体成功；PID仍由SSH采集、错误仍由本地日志检测，规则不能清除已记录错误或参与开机决策。样例通过不保证模型语义理解正确。

8. “全局 AI 设置 → 用量与消费”显示最近一次、今日（UTC+8）、累计输入/输出Token、缓存命中/写入及估计消费，列出最近50次调用。规则验证失败、返回不完整的请求也保存已返回用量；用量缺失显示未知，旧版本调用无法补算。独立账本 `.ui/ai_usage.sqlite3` 不保存日志正文或密钥。
9. “计价设置”填写美元/百万Token的Standard单价、Flex系数和估算汇率，绑定模型与API地址；优先按实际返回等级计价，未返回则按请求等级估算并注明。官方 `gpt-6-luna` 默认案例价为输入0.10、缓存命中0.01、写入0.125、输出0.50，Flex系数0.5；汇率7.0是估算设置，不是实时汇率。其它模型/接口需填写自己的单价。费用按调用时配置保存，后改价格不重算历史；缓存明细缺项暂按0估算并标注，最终以账单为准。[官方模型价格](https://developers.openai.com/api/docs/models/gpt-6-luna)

本轮API验收使用模拟响应；使用以前保存的真实203日志及用户实际缓存规则做本地回放，未连接203或4090，未外发日志或产生API费用。真实账单及人工桌面操作未验收。

### SSH连接复用与接入防护

训练监控默认每60秒采集；同一页面复用一个已认证的SSH长连接，不再每轮登录。一个SSH别名不能在两个页面同时启动。界面显示“采集次数 / 连接尝试次数”，保活每15秒发送SSH协议消息，不读取训练数据、不重新认证。

只用已有公钥登录，不尝试密码、其他用户名或其他端口。采集失败后按60、120、240、300秒退避；用户设置更长间隔时尊重该间隔。成功后恢复正常采样，停止/开始同一配置不能绕过尚未到期的失败退避。断连保留上次数据并标记过期，MaxStartups、认证失败与超时分别提示。

2026-10-03已在203-1单独实施服务端防护：仅允许公钥认证，未认证等待20秒，每连接最多3次认证尝试；保留原MaxStartups限制。该配置不是监控程序启动时自动下发的功能，4090与后来添加的服务器不会被自动修改。已有会话和训练不受本次配置重载影响。

迁移机器后，203的SSH也必须配置有效私钥或预先登记新公钥，平台账号登录不能替代SSH密钥。防护减少口令扫描造成的认证积压，不保证阻止公网连接洪泛；平台转发隐藏原始来源时，不应封禁容器看到的127.0.0.1。操作与回退位置记录在`Agent_MCP_Notes.md`。


## 配置与开机约束

- `config.yaml` 中 `auto_start.targets` 保存真实实例ID与入口；实例重建后应更新ID。未配置实例的入口只能只读监控。
- `monitor.poll_seconds` 是唯一采样间隔，默认60秒；旧双间隔界面偏好迁移到60秒，以后保存的自定义值保持不变。`occupancy` 仅保留本人用户名和连续缺席确认参数，兼容旧 `usage_tracking` 中的这两项；旧占用间隔、数据库和统计开关不再使用。
- 平台空位、物理显存、账号数量额度分别核验。无卡实例可能占用数量额度；不关闭有卡实例，不操作其他账号的实例。
- 关机前及有卡启动前核验目标入口空闲INDEX与新鲜显存达标INDEX一致。电源请求响应不明时只查询、不盲目重发；接口受理不等于有卡运行。
- 控制面请求默认直连；Telemetry沿用本机代理设置。每套浏览器资料同时只运行一个监控程序。
- Telemetry正常时沿用采样间隔，每次采集最多2次HTTP请求；连续失败按60/120/240/300秒冷却，到期后的下一采样轮再试。429不立即重试，Retry-After可延长等待。断连清理本采集器连接池，健康连接继续复用；停止监控释放HTTP会话。失败/冷却均跳过开机，不将旧显存数据当作当前结果，也不误报SSH或登录失效。

`runtime/`、`.ui/` 和 `.env` 属于本机资料，不纳入Git或发行包。更详细的API和验证约束见 `Agent_MCP_Notes.md`，历次变化见 `CHANGELOG.md`。
